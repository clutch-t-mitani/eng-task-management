# フロントエンド設計

## 4. フロントエンド設計

### Vue Router ルート定義

| パス | コンポーネント | 認証 |
|---|---|---|
| `/login` | LoginView.vue | 不要（ログイン済みなら /table へ） |
| `/` | redirect: /table | - |
| `/table` | TableView.vue | 要 |
| `/dashboard` | DashboardView.vue | 要 |
| `/issues` | IssueListView.vue | 要 |
| `/users` | UserListView.vue | 要 |
| `/users/new` | UserFormView.vue | 要 |
| `/users/:id/edit` | UserFormView.vue | 要 |
| `/engineers` | EngineerListView.vue | 要 |
| `/products` | ProductListView.vue | 要 |
| `/products/:id/repository` | ProductRepositoryView.vue | 要 |
| `/:pathMatch(.*)*` | redirect: /table | - |

ナビゲーションガード: `beforeEach` で `authStore.fetchMe()` を呼び、401 なら `/login` へリダイレクト。

### Pinia Store 設計

#### `stores/auth.js`
```
state:
  user: null | { id, name, email }
  isAuthenticated: boolean

actions:
  login(email, password)    → POST /api/v1/auth/login
  logout()                  → POST /api/v1/auth/logout
  fetchMe()                 → GET /api/v1/auth/me（ページリロード時の認証状態復元）
```

#### `stores/issues.js`
```
state:
  issues: Issue[]
  loading: boolean

actions:
  fetchIssues(params)
  updateIssue(id, data)         → 担当者・ステータス・管理対象などツール管理項目のみ更新
  updateStatus(id, statusId)   ← 楽観的更新（即時反映）
  toggleManaged(id)
  removeFromManaged(id)
  updateSchedule(id, schedule)
```

#### `stores/group.js`
```
state:
  groups: Group[]           # 各Groupにissuesプロパティあり
  ungroupedIssues: Issue[]
  loading: boolean

actions:
  fetchTable(params)        → GET /api/v1/table
  reorderGroups(ids)        → PATCH /api/v1/groups/reorder
  reorderGroupIssues(groupId, ids)  → PATCH /api/v1/groups/:id/issues/reorder
  createGroup(data)
  updateGroup(id, data)
  deleteGroup(id)
  moveIssueToGroup(issueId, groupId)
```

#### `stores/engineers.js`
```
state:
  engineers: Engineer[]

actions:
  fetchEngineers()
  createEngineer(data)
  updateEngineer(id, data)
  deleteEngineer(id)
```

#### `stores/products.js`
```
state:
  products: Product[]

actions:
  fetchProducts()
  createProduct(data)
  updateProduct(id, data)
  deleteProduct(id)
  reorderProducts(ids)
```

#### `stores/githubSync.js`
```
state:
  repositoryByProduct: { [productId]: { owner, repo, last_synced_at, last_sync_status } | null }
  syncing: { [productId]: boolean }
  lastResult: { [productId]: SyncLog | null }
  logs: { [productId]: SyncLog[] }

actions:
  fetchRepository(productId)        → GET    /api/v1/products/{id}/repository（404はnull扱い）
  saveRepository(productId, data)   → PUT    /api/v1/products/{id}/repository
  deleteRepository(productId)       → DELETE /api/v1/products/{id}/repository
  resyncNow(productId)              → POST   /api/v1/products/{id}/sync
                                       syncing[productId]=true → 完了でlastResultにSyncLog格納
                                       完了後 issueStore.fetchIssues() と groupStore.fetchTable() を再実行
  fetchLogs(productId, limit=20)    → GET    /api/v1/products/{id}/sync-logs?limit=20
```

#### `stores/filter.js`
```
state:
  productId: number | null
  engineerId: number | null
  directorId: number | null
  status_id: string[] // 初期値は完了以外（1=未着手、2=作業中、3=テスト中、5=保留）

getters:
  asParams   → 空値を除いた { product_id, engineer_id, director_id, status_id[] }

actions:
  setFilter(key, value)
  reset()
```

filterStore の変更を `TableView.vue` 内で `watch` → `groupStore.fetchTable(filterStore.asParams)` を再実行。

### 主要コンポーネントの責務

| コンポーネント | 責務 |
|---|---|
| `AppLayout.vue` | Sidebar + router-view の外枠レイアウト |
| `Sidebar.vue` | ナビリンク・ログアウトボタン。プロダクト管理と「リポジトリ連携設定」リンク |
| `TableView.vue` | fetchTable on mounted、グループ間D&D → reorderGroups()、filterStore watch、GitHub再同期ボタン制御、UnmanagedImportsPanelマウント |
| `IssueListView.vue` | ISSUE一覧をAPIから取得し、プロダクト・エンジニア・ディレクター・ステータス・管理表・日付範囲・フラグで絞り込む。エンジニア/ディレクターは「未割当」を選択可能。日付範囲はFrom/Toの逆転を送信前に検知し、各日付入力は個別クリアできる。適用中の条件はチップ表示し、チップ単位で解除する。ステータス初期値は完了以外で、初期条件のみの状態では絞り込み解除ボタンを無効化する。 |
| `GroupSection.vue` | グループヘッダー（名前・リリース日・件数・折りたたみ・削除）、グループ内D&D |
| `IssueRow.vue` | ステータスのインライン変更（楽観的更新）、日付4項目のインライン編集（blur時保存）、期日超過・期日間近フラグ表示。`github_issue_number` がある行は `github_state` バッジ（open=緑/closed=紫）と最終同期時刻ツールチップを表示 |
| `IssueEditModal.vue` | GitHubから取り込まれたIssueの管理項目編集（担当ディレクター・担当エンジニア・ステータス・グループ・日付4項目）。タイトル・URL・Issue番号は読み取り専用 |
| `FilterBar.vue` | filterStore.setFilter() を呼ぶ（モックの $emit('change') から変更） |
| `SummaryBar.vue` | 集計カード帯（総ISSUE・完了・作業中・期日超過・完了率） |
| `EngineerCard.vue` | API の dashboard レスポンスを props で受取（mockData 依存を除去） |
| `ConfirmDialog.vue` | 削除確認ダイアログ（汎用） |
| `UnmanagedImportsPanel.vue` | GitHubから取り込んだが `is_managed=false` のISSUE一覧。`unmanaged_imports=true` で取得、各行に「管理表に追加」ボタン（`PATCH /api/v1/issues/{id}/managed` を呼ぶ）。プロダクト未選択時は非表示 |
| `ProductListView.vue` | プロダクト一覧・追加・編集・削除・表示順変更。各プロダクトからリポジトリ連携設定へ遷移 |
| `ProductRepositoryView.vue` | プロダクトに紐付くGitHubリポジトリの登録・更新・解除画面。owner/repo フォーム、Webhook URL・Secret設定案内、最終反映日時・ステータス表示 |
| `GitHubResyncButton.vue` | TableView ツールバー配置の「GitHubから再同期」ボタン。プロダクト未選択時 / リポジトリ未登録時 / 同期中 で disabled。完了時はトーストで `作成 X / 更新 Y / スキップ Z / 失敗 W` を表示。失敗時は赤トースト + `error_message` を出す |
